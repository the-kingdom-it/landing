# Лендинг менторства в QA/AQA — дизайн

## Зачем

Одностраничный лендинг менторства Валентина Волкова: привести человека к бесплатному
созвону в Telegram. Главная особенность предложения — основная оплата после оффера.
Главное требование владельца — лендинг легко переделывать без знания React.

## Цели

- Все тексты, цены, ссылки, списки и FAQ — в одном типизированном файле `src/content.ts`.
- Цвета и шрифты — CSS-переменные в `src/app/globals.css`; акцент меняется в одном месте.
- Каждая секция — отдельный компонент в `src/components/sections/`; порядок — массив в
  `src/app/page.tsx`, секция убирается одной строкой.
- Статический экспорт (`output: "export"`), заливка на любой хостинг / VPS через nginx.
- `npm run build` проходит.

## Не цели / анти-цели

- Никаких выдуманных цифр, отзывов, статистики. Неизвестное — плейсхолдеры в `[КВАДРАТНЫХ СКОБКАХ]`.
- Никаких UI-библиотек, эмодзи, градиентов, карточек с цветной полосой слева.
- Никакого горизонтального скролла на телефоне.

## Ограничения (из ТЗ, дословно)

- Next.js (App Router) + TypeScript + Tailwind CSS, иконки — инлайн SVG (stroke).
- Фон #F3F4F1, текст #0F1115, вторичный #3D424A, бордеры #DCDED9, акцент #2B50FF, passed #1B7A43,
  тёмная секция #0F1115.
- Шрифты next/font с кириллицей: заголовки Unbounded 700, текст Inter, метки/моно JetBrains Mono.
- Контейнер 1200px, боковые отступы 24px, вертикальные отступы секций ~96px.
- Кнопки ≥44px, контраст ≥ WCAG AA, плавный скролл к якорям.
- Фото: `public/team/valentin.jpg`, `public/team/qa-lead.jpg`, путь в поле `photo`; `null` → серый
  скруглённый квадрат с инициалами. next/image unoptimized, 160×160 на десктопе, cover, радиус 16px, осмысленный alt.
- Секции и их порядок — см. ТЗ (Header, Hero, Кому подойдёт, Как проходит, Оплата, Команда,
  Реферал, FAQ, CTA, Footer). Meta title/description и Open Graph из content.ts, SVG-favicon с инициалами.

## Решения, принятые мной (проверь)

1. **Tailwind v4.** Актуальная версия; отдельного `tailwind.config` в v4 нет — его роль играет блок
   `@theme inline` в `globals.css`, который пробрасывает CSS-переменные в утилиты (`bg-accent`, `text-muted`…).
2. **Фото, которых нет на диске.** На момент сборки файлов в `public/team/` нет. Компонент при сборке
   проверяет существование файла: нет файла или `photo: null` → плейсхолдер, а не битая картинка.
3. **Favicon генерируется** при сборке (`/favicon.svg`): инициалы из `content.ts`, цвет — из `--accent`
   в `globals.css`. Так акцент и инициалы по-прежнему меняются в одном месте.
4. **Header/Footer** стоят вне массива секций (они не `<section>`, а `<header>`/`<footer>` вокруг `<main>`),
   но тоже убираются одной строкой. Массив — для секций внутри `<main>`.
5. **Шапка липкая только на ≥768px.** На телефоне навигация переносится на вторую строку, и липкая
   шапка съела бы пол-экрана.
6. **Кнопка «Узнать условия»** реферальной плашки ведёт на `#cta` (ссылка настраивается в content.ts).
7. **siteUrl** — плейсхолдер; пока он не валидный URL, `metadataBase`/`og:url` не выставляются.
   OG-картинка — необязательное поле `ogImage` (по умолчанию `null`).
8. **Тесты** — Vitest + Testing Library (требование TDD из глобальных инструкций). Отдельный тест
   проверяет, что в компонентах нет кириллицы, то есть тексты не захардкожены.
9. **Год в футере** вычисляется при сборке.
10. **Ветка** `feat/landing` прямо в репозитории (worktree невозможен: в репо нет ни одного коммита).
